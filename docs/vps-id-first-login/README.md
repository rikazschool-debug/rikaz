# حزمة مراجعة v2: أول دخول برقم الهوية لولي الأمر **والمعلم**

**للمراجعة فقط — لم تُطبَّق على أي خادم أو قاعدة.** تحل محل `docs/vps-guardian-activation` (تشمله كاملًا وتضيف المعلم).

## سبب رسالة «تعذر إرسال رمز لهذا الرقم»
الخادم (`_idl_resolve` في المنصة) يعرض هذه الرسالة نفسها لخمسة أسباب مختلفة، ولا يرسل أي رمز:

| السبب | المعنى | الحل |
|---|---|---|
| `not_found` | رقم الهوية غير موجود في سجلات المعلمين أو الموظفين أو أولياء الأمور | المدرسة تضيف/تصحح رقم الهوية في السجل |
| `no_account` | السجل موجود لكنه غير مربوط بحساب دخول — **الحالة الأشيع**: الحساب أنشأته المدرسة وينتظر «أول دخول» | هذه الحزمة (ولي الأمر والمعلم المعلّقان) |
| `conflict_account` | نفس الهوية مربوطة بحسابين مختلفين (مثلًا معلم وولي أمر بحسابين) | المدرسة توحّد الحساب |
| `no_phone` | لا يوجد جوال صالح في السجل | المدرسة تضيف الجوال |
| `conflict_phone` | السجلات بنفس الهوية تحمل أرقام جوال مختلفة | المدرسة توحّد الجوال في كل السجلات |

لمعرفة السبب الدقيق لأي رقم هوية **دون تغيير أي شيء**: `psql "$DB" -v nid=<رقم الهوية> -f diagnose_id_login.sql` (يطبع السبب وأي سجل مطابق مع آخر 3 أرقام فقط من الجوال).

## ما تضيفه v2 على حزمة ولي الأمر
- `_idl_resolve_staged_teacher`: معلم أنشأت المدرسة حسابه (`account_setup` نوع `teacher`، بانتظار تأكيد الجوال) يُرسل له الرمز على جوال سجله، وبعد صحة الرمز فقط يُفعَّل ويُربط — نفس شروط ولي الأمر تمامًا.
- معلم ما زال مطلوبًا منه تغيير كلمة مرور وضعها المالك لا يُفعَّل بالهوية (البوابة تبقى في الموقع).
- البريد الداخلي لحساب المعلم بلا بريد: `‹الهوية›@staff.rikaz.app` (نطاق المنصة نفسه).
- لا تغيير على: المعلمين والموظفين المفعّلين، الموظفين بأسماء مستخدمين، الطلاب، المالك.

## الاختبارات (Postgres محلي مؤقت ببيانات وهمية)
`test/run.sh`: **54 فحصًا ناجحًا** (44 السابقة + 9 للمعلم المعلّق) مع التزامن والتراجع، و6 اختبارات Jest لخطوة البريد.

## حالة مكتشفة على الخادم (2026-11-18)
ولي أمر غيّرت المدرسة جواله: بقي له حسابا دخول معلّقان — القديم بالجوال السابق والجديد بالجوال الحالي — فكانت الحزمة السابقة ترفضه بـ`conflict_account`.
الآن يُتجاهل الحساب المعلّق القديم ما دام سجل المدرسة واحدًا، ويُرسل الرمز فقط للحساب الذي يحمل جوال السجل الحالي (اختبار 12). جُرّبت الحزمة على قاعدة الخادم داخل معاملة أُلغيت بالكامل، وحددت الحساب الصحيح.

## قبل النشر (تحتاج موافقتك)
1. شغّل `diagnose_id_login.sql` على رقم هوية متأثر لتتأكد أن السبب `no_account` وأن هناك صفًا معلّقًا.
2. نسخة احتياطية → staging → `test/run.sh` → تجربة بحساب اختبار.
3. التراجع: `supabase/rollback/…down.sql` وإرجاع `verifyIdCode`.
