# اتصال الجوال بالـVPS — 17 نوفمبر 2026

## ما تم التحقق منه

- `https://app.kalmalki.com` يعرض المنصة (HTTP 200).
- تم التحقق من المفتاح العام لتطبيق الجوال محليًا، ويعيد `https://api.kalmalki.com/auth/v1/health` استجابة HTTP 200 عند استخدامه.
- GET إلى المسارات المنشورة `request-code` و`verify-code` و`student-login` يعيد HTTP 405 مع JSON؛ المسارات موجودة وترفض طريقة GET.
- لم يُرسل أي طلب POST، ولم يُطلب رمز واتساب أو تُستخدم هوية/حساب حقيقي. رد 405 لا يثبت قبول تسجيل دخول فعلي.
- خدمات الدخول منشورة على `https://app.kalmalki.com/api/public/auth/`، وخدمات Supabase على `https://api.kalmalki.com`.
- يبقى `EXPO_PUBLIC_MOBILE_ID_LOGIN=0` حتى قبول اختباري الطالب وولي الأمر من جهاز/حساب مصرح بهما.
- MCP المتاح يقرأ مخطط جداول VPS فقط؛ ليس أداة نشر أو جلسة مستخدم ولا يوفّر مفاتيح خادمية.

## إعدادات التطبيق

استخدم قيم `.env.example`: عنوان قاعدة VPS والمفتاح العام الخاص بها. عنوان `EXPO_PUBLIC_AUTH_API_URL` مستقل ويشير إلى أصل تطبيق VPS، بينما `EXPO_PUBLIC_PLATFORM_URL` لفتح الويب فقط. المسار `/api/public/auth/…` يضيفه التطبيق. **لا تستخدم مفتاح السحابة القديم**، ولا أي مفتاح خدمة أو JWT signing secret أو بيانات WATI في `EXPO_PUBLIC_*`.

الدخول بالهوية يبقى `EXPO_PUBLIC_MOBILE_ID_LOGIN=0` حتى اختبار الطالب وولي الأمر واعتماد النتيجة. معاينة النموذج في التطوير يمكن إظهارها عبر `EXPO_PUBLIC_MOBILE_LOGIN_PREVIEW=1`، لكن أزرارها معطلة، ولا ترسل أي طلبات.

## حزمة خدمات جاهزة للمراجعة، وليست منشورة

`vps-auth-overlay/` يحتوي ثلاث routes وطبقة HTTP محدودة المدخلات، ومساعد الدخول المستخرج من نسخة المنصة المرجعية. الملف البديل `id-login.functions.ts` يجعل الويب وHTTP يعيدان استخدام **المساعد نفسه** بدل مسارين متباعدين. المساعد يحتفظ بـ`_idl_issue`, `_idl_verify`, `_idl_portal_ok`, `_idl_student`, `_idl_student_finish` وإرسال WATI والتسجيل وإصدار magiclink لحساب موجود فقط. لا SQL ولا تغيير RLS ولا إنشاء حساب.

يجب مقارنة المصدر مع **إصدار VPS الجاري** قبل استخدام الحزمة؛ نسخة المشروع المقروءة ليست إثباتًا أن نشر VPS مطابق. التحويل المراجع يحتفظ بسلوك المنصة ولا يضيف مزود إرسال أو حسابات أو صلاحيات. تحقق الهوية يجري خادميًا قبل إصدار الرمز؛ استخدام admin هنا مقصور على وظائف الدخول القائمة. العضويات والبيانات لاحقًا تُقرأ بجلسة المستخدم وبسياسات VPS القائمة.

## النشر والرجوع — يحتاج منفّذًا مخوّلًا على VPS

1. سجّل commit وصورة التطبيق الجاريين، وافحص حالة Git في مصدر VPS. لا تعمل في نسخة معدلة محليًا، ولا تغيّر بيانات الاعتماد أو قاعدة البيانات.
2. قارن المساعد بملف الدخول الجاري وراجع تغييرات المنصة منذ نسخة المرجع. طبّق overlay في فرع مراجعة منفصل؛ لا تنسخه بلا مقارنة. حافظ على منطق OTP والأدوار القائم.
3. نفّذ اختبارات المنصة وTypeScript وبناء Node في بيئة معزولة؛ لا تشغّل ترحيلات ولا seed ولا رسائل. ملاحظة: اختبارات الجوال للـHTTP تستخدم نتائج وهمية وتثبت حدود المدخلات فقط.
4. راجع Nginx لمسارات `/api/public/auth/request-code`, `/verify-code`, `/student-login` بحيث تمر إلى التطبيق، لا API gateway. لا تفتح `/send-sms` ولا منافذ داخلية ولا لوحات الإدارة. انسخ كتلة Nginx السابقة وافحص `nginx -t` قبل إعادة تحميله.
5. ابنِ صورة مراجعة فريدة مع إعداد VPS العام، وشغّل **خدمة التطبيق فقط** باستخدام إجراء `infrastructure/vps-app/README.ar.md` الموجود في المنصة. يلزم وصول تنفيذي مخوّل إلى Docker وNginx وملفات إعداد VPS الموجودة؛ لا حاجة لتغييرها أو إظهار محتوياتها.
6. قبول فعلي بحساب اختبار محدد ومصرّح به: الطالب بالهوية وC-Smart، وولي الأمر/الموظف برمز يصل إلى جوال الاختبار. لا تستخرج OTP من قاعدة البيانات ولا تتجاوز `_idl_*`. استبدل hashed token عبر Auth VPS، ثم اقرأ المستخدم والعضويات الفعالة واختر المدرسة واستدعِ صلاحياتها واقرأ بيانات مسموحة فقط. قارن النتيجة بمنصة VPS للحساب نفسه؛ تحقق أيضًا من رفض بيانات خارج نطاقه.
7. لا تفعّل 1 في إعدادات المستخدم قبل قبول الخدمات. اختبر الهاتف/المحاكي محليًا منفصلًا عن تصدير JavaScript.
8. الرجوع: أعد صورة التطبيق وكتلة Nginx المحفوظتين فقط، وأعد علم الدخول إلى 0. لا تستعد قاعدة ولا تحذف volumes ولا تنفّذ `compose down` ولا تغيّر مفاتيح المصادقة.

## تحديث Windows دون فقد .env

```powershell
Set-Location "$env:USERPROFILE\rikaz-mobile"
git status --short
```

إذا ظهرت تعديلات: توقّف وراجعها قبل التحديث؛ لا نستطيع معرفة حالة جهازك أو استرجاع stash آليًا. إذا كانت الحالة نظيفة، حدّث develop بإجراء Git المعتاد لديك. افتح `.env` محليًا، وحدّث فقط قيم الاتصال الخمس من `.env.example` مع الحفاظ على بقية القيم. لا تستبدل `.env` الموجودة ولا تعرض محتوياتها في الدردشة.

```powershell
npm.cmd install
npm.cmd run typecheck
npm.cmd test
npx.cmd expo start -c --android
```

## حدود الإنجاز

فحوص هذه الدفعة: فحص TypeScript نجح، و4 مجموعات Jest تضم 25 اختبارًا نجحت. فحص syntax لملفات overlay نجح، لكن بناء المنصة مع overlay وفحصها على VPS لم ينفذا. لم تُجرَ بناءات Android/iOS أصلية أو تشغيل جهاز أو محاكي أو دخول بحساب فعلي.

المفتاح العام وصحة Auth VPS متحققان. لا يوجد حتى الآن حساب اختبار محدد أو أداة تنفيذ VPS في هذه المحادثة؛ نشر الخدمات وإصدار جلسة وقراءة العضويات والصلاحيات والبيانات فعليًا **غير متحقق**. لا تعتبر فحص health أو الاختبارات المعزولة أو عرض النموذج بديلًا عن ذلك.
