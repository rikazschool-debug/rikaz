## ما الذي تحله
ولي أمر أنشأت المدرسة حسابه (معلّق في `account_setup` بانتظار تأكيد الجوال) يحصل اليوم على `no_account`. بعد الحزمة: يُرسل الرمز إلى جوال سجل المدرسة، وبعد صحته فقط يُفعَّل الحساب نفسه ويُربط.

| لا ربط ولا تفعيل ولا صلاحيات قبل الرمز | الإصدار يكتب صف التحدي فقط. اختبارات: غير مربوط / عضوية غير مفعّلة / جوال غير مؤكد قبل الرمز، والرمز الخاطئ لا يغيّر شيئًا |

## إصدار الجلسة بعد التفعيل
1. `_idl_verify` يعيد `activated` و`needs_login_email` و`login_nid` للخادم فقط (لا تصل للتطبيق).
2. إن لم يكن للحساب بريد: `ensureGuardianLoginEmail` يضيف `‹الهوية›@guardian.rikaz.app` مؤكدًا عبر واجهة الإدارة. هذا ليس بريدًا وهميًا خارجيًا: هو نطاق المنصة الذي يستخدمه دخول الويب الحالي لأولياء الأمور (`src/lib/guardian-login.ts`)، ولا يُرسل إليه أي بريد. لا يستبدل بريدًا موجودًا، ويرفض إن كان العنوان لحساب آخر.
3. `tokenFor` الحالي: `generateLink({type:"magiclink"})` يعيد `hashed_token` للتطبيق مباشرة، والتطبيق يفتح الجلسة بـ `verifyOtp({ token_hash, type: "magiclink" })` — لا تغيير في التطبيق.
4. إن فشلت الخطوة 2 بعد التفعيل: الطلب التالي يمر بالمسار العادي و`needs_login_email` يبقى صحيحًا، فتُعاد المحاولة دون تفعيل مزدوج.

**بديل بلا بريد إطلاقًا (لم يُعد):** تفعيل دخول الجوال في GoTrue مع Send SMS Hook يرسل عبر واتساب، ثم `verifyOtp({ phone, token, type: "sms" })`. يتطلب تغيير إعدادات المصادقة في الخادم.
